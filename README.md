## Собственная атака по CRP

Реализована модель итогового ответа Arbiter / XOR Arbiter PUF по ранее измеренным парам запрос–ответ. Модель обучается отдельно для каждого устройства; на тесте используются новые запросы того же устройства. Исходные веса и ответы отдельных цепочек алгоритму обучения недоступны.

Две независимые серии по 12 синтетических устройств, 64-битные запросы, бюджеты 256 / 1024 / 4096 обучающих CRP, 512 дополнительных CRP для выбора одного из трёх стартов и 2048 тестовых запросов. Все выборки запросов не пересекаются; основной и повторный прогоны используют разные устройства. Интервалы — бутстрэп по устройствам, 4000 повторов.

Точность модели произведения задержек при 4096 обучающих CRP; в скобках — точечные 95%-е интервалы:

| Схема | Шум σ | Основной прогон, % | Независимый повтор, % |
|---|---:|---:|---:|
| Arbiter | 0,0 | 98,87 [98,76; 98,99] | 98,90 [98,79; 99,01] |
| Arbiter | 0,1 | 96,24 [95,82; 96,65] | 96,45 [96,14; 96,75] |
| 2-XOR | 0,0 | 98,24 [98,09; 98,40] | 98,31 [98,06; 98,54] |
| 2-XOR | 0,1 | 92,30 [91,83; 92,66] | 92,90 [92,46; 93,36] |
| 4-XOR | 0,0 | 50,13 [49,71; 50,59] | 49,51 [49,00; 50,04] |
| 4-XOR | 0,1 | 50,22 [49,61; 50,79] | 50,26 [49,86; 50,64] |

Для 2-XOR с шумом выигрыш относительно константы — **39,84 п. п.** [95% ДИ: 38,05; 41,64]. Линейная LR дала 53,28%, контроль с перемешанными метками — 51,08%. Для 4-XOR при этих ресурсах обучение не дало убедительного выигрыша. Это ограничение эксперимента, а не доказательство криптографической стойкости.

Сравнения учитывают различие в доступных данных: константа и линейная LR используют только обучающий бюджет; модель произведения дополнительно использует валидацию для выбора старта. Константа обучается на истории данного устройства и может превышать 50% за счёт его смещения. Она не относится к сценарию полного отсутствия CRP.

В основной серии 39 из 216 выбранных запусков завершились без флага сходимости, в повторе — 35 из 216. Эти запуски оставлены в итоговых оценках. 12 устройств на серию дают ограниченную оценку вариативности; интервалы не скорректированы на множественные сравнения. Собственные результаты получены на симуляторе, аппаратные данные используются только в обзоре публикаций.

## Разные запросы, повторы и корреляция шума

Дополнение из плана проверяет именно качество атаки при равном числе физических обращений к PUF. Бюджеты обучения — 4608 и 18432, ещё 512 общих валидационных обращений. Число чтений одного запроса — 1, 3 или 9; обучающая метка — большинство. Для Arbiter и 2-XOR сравниваются независимые и коррелированные ошибки повторов (ρ = 0 и 0,9) при σ = 0,25. Маргинальная дисперсия шума и первое чтение совпадают между режимами корреляции.

Расширенный benchmark включает 3-XOR, 4-XOR и MLP (64 → 32 скрытых нейрона, tanh, Adam, 40 эпох). Модель произведения задержек и MLP имеют одинаковые обучающие и валидационные данные и по два старта. В каждой серии пять устройств; полный повтор использует пять новых устройств. В таблице времени учитываются все старты, выбор на валидации и предсказание; генерация данных исключена. На время влияет параллельная нагрузка.

При 18432 разных обучающих запросах (+512 валидационных), без шума, модель произведения задержек дала:

| Схема | Основная серия, % | Независимый повтор, % |
|---|---:|---:|
| Arbiter | 99,62 | 99,66 |
| 2-XOR | 99,50 | 99,66 |
| 3-XOR | 99,39 | 99,56 |
| 4-XOR | 99,23 | 99,39 |

В той же расширенной серии при 4608 CRP точность 4-XOR составляла 50,63% (повтор 48,82%). При 18432 CRP она превысила 99%. Поэтому неудача атаки при малом бюджете не является подтверждением стойкости схемы. MLP при большом бюджете без шума дала 98,75%, 97,89%, 89,98% и 50,21% для 1–4 цепочек; это результаты выбранной архитектуры и лимита 40 эпох.

**Результат равного бюджета.** Для 2-XOR, B = 18432 и σ = 0,25 переход от одного чтения к девяти коррелированным (ρ = 0,9) снизил accuracy с 85,74% до 84,13%: разность −1,61 п. п. [95% ДИ: −2,41; −0,88]. В повторе разность −1,84 п. п. [−2,41; −1,21]. Даже независимые девять чтений снизили ошибку обучающих меток до 6,67%, но дали меньшую точность — 84,92%. Для трёх чтений результаты слабее и неоднозначны; общего правила превосходства одной стратегии для всех условий не заявляем.

У последней проверена аннотация издателя, полный текст недоступен. Поэтому использование долей повторных ответов само по себе не объявляется новым методом; сравнение с этими алгоритмами по численным результатам не выполнено.

Симулятор отдельно сопоставлен с **pypuf 3.2.1** на одинаковых весах и запросах: 262144 ответных бита, 16 устройств, 1–4 цепочки, **0 расхождений**. [Протокол](results/reference/pypuf_check.json). Это проверка функции ответа, не эквивалентности распределений генераторов весов.

Математическое дополнение (раздел 16 отчёта) выводит верхнюю границу через информацию гауссовских задержек: при фиксированном B коэффициент равен B / {σ²[1+(r−1)ρ]}. [Проверка матричной формулы](results/reference/information_bound.csv). Она поясняет ограничение усреднения при корреляции, но не доказывает универсального порядка accuracy бинарных атак.

## Дополнение из раннего плана: доли ответов и бинарная информация

Вместо одного бита большинства атака теперь может обучаться на доле ответов «1» среди тех же 3 или 9 чтений. Используется BCE, линейная по этой доле: она точно равна средней BCE всех измеренных битов. Бюджет, исходные запросы, шум, начальные веса, регуляризация и выбор старта по валидации совпадают с основной серией. Выполнены 160 обучений с двумя стартами каждое на тех же 5 + 5 устройствах. Это расширение сравнения известных способов использования повторов, без заявления мирового приоритета.

Для **2-XOR, B = 4608, σ = 0,25 и девяти независимых чтений**:

| Обучающая метка | Основная серия, % | Независимый повтор, % |
|---|---:|---:|
| Большинство | 62,35 | 62,97 |
| Доля ответов | **83,86** | **82,93** |
| Один ответ на каждый новый запрос | 85,13 | 83,61 |

Парный выигрыш мягких меток над большинством — **21,50 п. п. [18,34; 24,03]**, повтор — **19,96 п. п. [14,94; 24,93]**. Превосходство над новыми запросами не установлено: соответствующие разности составили −1,27 п. п. [−1,68; −0,67] и −0,68 п. п. [−1,38; 0,01]. При других бюджетах и корреляциях эффект меняется; все условия сохранены, включая неоднозначные и отрицательные результаты. Для невыпуклой модели эффект может отражать как сохранённую информацию, так и изменение оптимизации.

**Уточнение после проверки оптимизации.** В исходном сильном эффекте модели большинства достигали лимита 180 итераций. Дополнительный контроль на тех же данных сравнил 1000 итераций, восемь стартов и увеличение L2 с 0,0001 до 0,01. При последней настройке точность большинства выросла до 79,18%, долей — 83,79%; парный выигрыш уменьшился до **4,61 п. п. [2,21; 7,01]**. В повторе — **4,94 п. п. [3,50; 6,51]**. Все выбранные модели этой настройки сошлись. Поэтому исходный размер эффекта нельзя приписывать только информации метки: он существенно зависит от обучения и регуляризации. Контроль выполнен после основной серии, полного поиска настроек не было.

Математическое дополнение рассматривает **бинарный**, а не аналоговый ответ одной цепочки при известном масштабе независимого шума. Для T физических обращений и r чтений каждого случайного запроса условная информация удовлетворяет E[Jᵣ] = T E[I(c)] и Cov(vec Jᵣ) = rT Cov(vec I(c)). Доля ответов сохраняет информацию независимых Bernoulli-повторов, большинство в общем случае теряет её. Например, при вероятности единицы 1/2 большинство трёх чтений сохраняет 75% информации всех трёх битов.

Проверены **24000 случайных планов запросов**: два фиксированных PUF, по 4000 планов для r = 1, 3, 9; T = 576, σ = 0,75. Отношения дисперсий при r = 3 и 9 получились **2,98 и 8,63**; для другого PUF — **2,88 и 8,90**, при теоретических значениях 3 и 9. Интервалы и исходные значения сохранены. Запросы здесь выбираются с возвращением для точного тождества; обучение атаки использует разные запросы. Формулы не переносятся автоматически на коррелированный шум и не определяют порядок конечной accuracy.

## Новые устройства: учитывать вероятность самого голосования

Дополнительная проверка выясняет, сохраняется ли преимущество долей после учёта распределения наблюдения при голосовании. Для двух цепочек с независимым гауссовским шумом реализована вероятность итогового XOR через нормальную функцию распределения. Если из девяти битов оставлено большинство, вероятность этой метки — биномиальная хвостовая вероятность G₉(p), а не вероятность одиночного ответа p. Сравниваются разные запросы, наивная модель большинства, модель G₉(p) и доли ответов.

**Протокол и хеши научного кода зафиксированы до генерации новых данных.** Это локальная фиксация, без внешней регистрации. Основная серия и повтор содержат по **16 новых устройств**, не использованных в предыдущих опытах или пилоте. Условия: 64-битный 2-XOR, σ = 0,25, независимый шум, B = 4608 обучающих + 512 валидационных обращений, 8192 тестовых запроса. По 4 старта и 4 коэффициента L2, максимум 1000 итераций; настройка каждого метода выбирается по одному и тому же валидационному log loss. Истинные задержки и вероятности в обучение не поступают.

| Метод | Основная серия, % | Независимый повтор, % |
|---|---:|---:|
| Разные запросы, одно чтение | 84,65 | 84,45 |
| Большинство, наивная модель | 79,29 | 79,39 |
| Большинство, учёт его вероятности | 78,66 | 78,95 |
| Доли ответов | 84,11 | 84,06 |

Первичный контраст «доли − модель G₉» — **5,45 [4,72; 6,15] п. п.**, повтор — **5,12 [4,68; 5,58] п. п.** Преимущество сохранилось в обеих новых сериях. Во вторичном сравнении доли уступили разным запросам: -0,54 [-0,72; -0,35] и -0,39 [-0,62; -0,17] п. п. соответственно. Корректная вероятность большинства не дала подтверждённого выигрыша accuracy над наивной моделью.

Выполнено 2048 обучений-кандидатов; все 128 выбранных моделей получили флаг сходимости. Сохранены веса **каждого** кандидата, валидационные оценки, прогнозы, метрики и парные интервалы. Это ограниченный опыт с заранее заданным сравнением на новых устройствах: он не устанавливает мировой приоритет метода, глобальный минимум или универсальную пользу повторов. Новые числа относятся к иному протоколу и не являются прямой заменой оценок раздела о прежнем контроле оптимизации.

## Дополнения из ветки Ivan: фиксированные и адаптивные повторы

Интегрированы два дополняющих исследования из [коммита b8d12e7](https://github.com/Alfasamec3D/Info_protect/commit/b8d12e7d7f638fd3846538d0a72da4ef2ebc1dee). Исходный научный код сохранён без изменений; [происхождение и контрольные суммы](configs/ivan/origin.json) отделяют его от нового адаптера запуска, агрегации и независимого аудитора. Пересекающиеся 750 базовых запусков и информационный анализ ветки повторно не включены в общий объём результатов.

**Фиксированные повторы: 100 новых Arbiter PUF, 300 обучений.** При σ = 0,75 и общем бюджете 4096 чтений доли пяти ответов точнее большинства на **2,721 п. п. [2,554; 2,888]**, но уступают разным запросам на **0,193 п. п. [0,031; 0,356]**. Здесь accuracy относится к ответам без шума, а не к новому шумному чтению. Интервалы учитывают два первичных сравнения по Бонферрони. [Метрики](results/ivan/confirmation/summary.csv) · [Контрасты](results/ivan/confirmation/contrasts.csv)

**Адаптивные повторы: 100 других Arbiter PUF, 3200 обучений в восьми условиях.** Правило «3 или M» останавливает измерения после трёх одинаковых ответов, иначе продолжает до M = 5 или 15. При вероятности ответа p доля Q = S/N оказывается смещённой:

```text
E[Q] = p + (1 − 3/M)p(1 − p)(2p − 1).
L = Σ N · BCE(S/N, p).
```

Вторая формула — отрицательный логарифм правдоподобия с учётом фактического числа чтений. Его применение вместо невзвешенной BCE по долям уменьшило **MSE вероятности на 16,3–83,0%**. Все восемь парных интервалов разности исключают ноль после поправки Бонферрони. Проверены два шума, два бюджета и два предела повторов; все 3200 моделей сошлись. [Метрики](results/ivan/stopping/summary.csv) · [Контрасты](results/ivan/stopping/contrasts.csv) · [Эффекты](results/ivan/stopping/primary_contrasts.png) · [Смещение](results/ivan/stopping/stopping_bias.png)

Это улучшение оценки вероятностей в выбранной модели, а не такой же рост accuracy бинарной атаки. Превосходства над разными запросами во всех условиях нет. Общие свойства оценок при остановке известны; мировой приоритет частного результата не установлен. Заявление исходного протокола о фиксации после пилота не имеет внешней временной аттестации. Исследование ограничено симулированным одиночным Arbiter и независимым шумом. Подробности и источники — разделы 22–24 отчёта и [обзор](report/related_work.csv).

```sh
build/verification-env/bin/python -m puf_lab.ivan_studies --profile smoke --workers 2 --output build/ivan-demo
build/verification-env/bin/python report/check_ivan.py --results build/ivan-demo --workers 2
build/verification-env/bin/python -m puf_lab.ivan_studies --workers 6 --output build/ivan-full
build/verification-env/bin/python report/check_ivan.py --results build/ivan-full --workers 6 --write-audit
```

Запускать из корня репозитория, указывая новый каталог вывода. Полный `puf_lab.reproduce` также включает обе серии. Аудитор независимо восстанавливает измерения и траектории остановки, проверяет сохранённые веса, градиенты, непересечение выборок, бюджет, метрики и интервалы. Исходная ветка использовала другие версии Python/NumPy/SciPy; интегрированные результаты пересчитаны в окружении `constraints-study.txt`, а побайтовая идентичность между разными окружениями не предполагается.

## Выводы

1. **Наблюдатель никогда не имел пар конкретного экземпляра.** Для фиксированного запроса вероятность 50% следует из симметрии условного распределения ответа. Независимые центрированные цепочки дают такую симметрию. В контрольных сериях на симуляторе измерена доля единиц при систематическом сдвиге и корреляции цепочек. [Контроль со сдвигом](results/unseen_device.csv), [контроль корреляции](results/sensitivity/spatial_bias.csv)
2. **Ранее измеренные пары доступны, сейчас физического доступа нет.** Опубликованы аппаратные контрпримеры непредсказуемости на новых запросах того же экземпляра. Таблица указывает схему, происхождение данных, условия, метрику и точное место каждого значения. [Первичные источники и результаты](report/evidence.csv)
3. **Собственная атака предсказывает новые ответы того же устройства.** Модель произведения задержек обучается только по старым CRP. Результаты, независимый повтор и ограничения приведены выше.
4. **Дополнительная ML-часть оценивает агрегированный BER следующей сессии.** Калибровочные признаки и целевое значение вычисляются из разных сессий. В каждом режиме 1024 обучающих, 256 валидационных и 512 тестовых устройств. Полный повтор заново генерирует экземпляры и обучает модели. [Основной прогон](results/forecast/metrics.csv), [повтор](results/forecast/repeat/metrics.csv)

| Режим | Метод | MAE основного прогона, п. п. | MAE повтора, п. п. |
|---|---|---:|---:|

| Без дрейфа | Ridge | 0,66 | 0,69 |
| Без дрейфа | Бустинг | 0,66 | 0,69 |
| Устойчивый дрейф | Текущий BER | 1,42 | 1,42 |
| Устойчивый дрейф | Ridge | 1,40 | 1,39 |
| Устойчивый дрейф | Бустинг | 1,43 | 1,44 |
| Изменчивый дрейф | Текущий BER | 8,08 | 8,25 |
| Изменчивый дрейф | Ridge | 5,71 | 5,98 |
| Изменчивый дрейф | Бустинг | 6,05 | 6,14 |

Для изменчивого дрейфа выигрыш Ridge относительно правила равен 2,36 п. п. с парным 95%-м интервалом 1,90–2,84 п. п. В повторе выигрыш равен 2,27 п. п. с интервалом 1,77–2,77 п. п. При устойчивом дрейфе интервалы обеих моделей включают ноль в обеих сериях. CSV хранит доли от 0 до 1. В отчёте, таблице выше и графиках ошибки приведены в процентных пунктах. [График основного прогона](results/forecast/forecast.png), [график повтора](results/forecast/repeat/forecast.png)

### Перенос между режимами

Дополнительная проверка переносит каждую обученную модель на тестовые экземпляры двух других режимов. Модели и параметры стандартизации заморожены. Ошибки модели и правила текущего BER сравниваются на одних и тех же целевых экземплярах. Интервалы вычислены парным бутстрэпом по устройствам.

| Обучение → проверка | Модель | Выигрыш по MAE в основном прогоне, п. п. | Выигрыш в повторе, п. п. |
|---|---|---:|---:|
| Изменчивый → без дрейфа | Ridge | −12,14 | −11,91 |
| Устойчивый → изменчивый | Бустинг | +0,48 | +0,32 |

В первом случае при переносе MAE составила 12,87 п. п. против 0,74 у правила текущего BER. Основной 95%-й интервал выигрыша составил от −12,52 до −11,76 п. п. Во втором случае интервалы выигрыша положительны в обоих прогонах. Эти эффекты относятся к указанным симулированным условиям. [Основная матрица](results/forecast/transfer_metrics.csv), [независимый повтор](results/forecast/repeat/transfer_metrics.csv), [график](results/forecast/transfer.png)

**Статус курсовой.** Реализована собственная атака на симулированные PUF и выполнено исследование надёжности. Аппаратные измерения не проводились; соответствие ожиданиям и оценку определяет семинарист. [Таблица требований](report/requirements.md)

## Демонстрация проверки одноразового запроса

В прототипе устройство отвечает на свежий одноразовый запрос тегом HMAC-SHA-256 с отдельным случайным ключом. Проверяющий привязывает запрос к устройству, проверяет срок и при успехе атомарно погашает запрос. В тестах проверяются повторное предъявление, срок действия, ключ другого устройства и два конкурентных предъявления одного запроса. [Спецификация HMAC](https://www.rfc-editor.org/rfc/rfc2104), [принцип свежего запроса у NIST](https://pages.nist.gov/800-63-4/sp800-63b.html#single-factor-cryptographic-verifiers)

```sh
build/verification-env/bin/python -m puf_lab.defensive_auth --output build/defense-demo
```

Демонстрация работает в одном процессе с программными тестовыми ключами. Ключ не выводится из PUF; проверка повторов не доказывает защиту от моделирования ответов. Результат каждого теста записывается в JSON. [Код демонстрации](src/puf_lab/defensive_auth.py) · [Исходы проверок](results/defense/nonce_checks.json)

## Воспроизведение из чистого окружения

В Git хранятся исходники, конфигурации, тесты, CSV-таблицы, манифесты, протоколы проверок, графики и итоговые документы. Веса моделей, массивы NPZ, трассы обучения и дублирующие JSONL исключены через `.gitignore`; локальные файлы сохраняются. Поэтому сразу после клонирования проверку сохранённых моделей нужно выполнять на заново рассчитанном каталоге `build/verified-results` по командам ниже. Полный локальный архив для независимой проверки содержит и эти данные.

Команды для Linux из корня репозитория. Воспроизведение проверено на Python 3.10.12. pypuf устанавливается отдельно без зависимостей: здесь используется только его симулятор на NumPy/SciPy, а старый TensorFlow не требуется. Для экспорта PDF нужен LibreOffice. Для проверки готовых PDF нужна команда `pdftotext` из Poppler.

```sh
python -m venv build/verification-env
build/verification-env/bin/python -m pip install -c constraints-study.txt '.[report]'
build/verification-env/bin/python -m pip install --no-deps --target build/pypuf-reference pypuf==3.2.1
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 build/verification-env/bin/python -m unittest discover -s tests -v
build/verification-env/bin/python -m puf_lab.reproduce --output build/verified-results --jobs 4 --query-workers 5 --pypuf-path build/pypuf-reference
build/verification-env/bin/python report/build.py --results build/verified-results --output build/verified-report
build/verification-env/bin/python report/export.py --report build/verified-report
build/verification-env/bin/python report/check.py --results build/verified-results --report build/verified-report
```

Следующее сравнение всех файлов применимо, когда в `results/` есть полный эталонный набор, включая модели и массивы: например, после распаковки полного архива. В обычном клоне Git этих файлов нет; проверка `report/check.py` выше самостоятельно восстанавливает данные и проверяет свежие модели, метрики и интервалы.

```sh
build/verification-env/bin/python report/compare_runs.py --reference results --repeated build/verified-results --output build/reproduction-comparison.json
```

Полный запуск пересчитывает результаты всех серий, включая две серии атаки по CRP, мягкие метки, бинарный информационный анализ и 3500 моделей дополнений из ветки Ivan, и повторяет тесты одноразовых запросов. Мягкие метки рассчитываются после завершения базовых серий бюджета, чьи измерения они используют; затем выполняется контроль оптимизации и регуляризации и две серии по зафиксированному протоколу вероятности наблюдения на новых устройствах. Экспорт корректирует оглавление по фактическим страницам PDF. Среди серий равный бюджет запросов с MLP и коррелированными повторами, сравнение с pypuf, контроль симметрии, межсессионный эксперимент, корреляция, калибровка по лагам и оба ML-прогона. `--jobs` задаёт число независимых параллельных задач. Для дополнительной серии `--query-workers` задаёт число процессов по устройствам. Если ресурсов мало, уменьшите оба параметра до 1. Численные результаты не зависят от параллельности; измеренное время обучения зависит. Для демонстрации подходит короткий профиль.

```sh
build/verification-env/bin/python -m puf_lab.forecast_cli --profile smoke --output build/demo
```
