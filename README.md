# ML-атаки на физически неклонируемые функции

Курсовой проект: моделирующие атаки на Arbiter и XOR Arbiter PUF и исследование распределения бюджета запросов при шуме. Команда: Иван Шаверин, Антон Хмельницкий, Максим Рачинский.

Реализованы аддитивная модель задержек, гауссовский шум, логистическая регрессия, структурная XOR-модель с произведением tanh и MLP. Контрольные модели — константное предсказание и регрессия на исходных challenge. Реализации на NumPy/SciPy; GPU не требуется.

## Исследовательский вклад: адаптивное число повторов

Основной исследовательский результат новой версии — **смещение мягких меток при зависящем от ответов сборе CRP и его учёт в likelihood атаки**. Для правила «остановиться после трёх одинаковых ответов, иначе измерять до M» выведены точная формула искажения метки и ненулевая производная популяционной soft-BCE в истинных параметрах probit-модели. Корректный likelihood использует и число положительных ответов S, и число измерений N.

Независимая проверка: 100 новых PUF, 8 заранее заданных режимов, 4 метода — 3200 обучений. Среднеквадратичная ошибка вероятностей снижена на 16–83% относительно невзвешенного обучения по тем же адаптивным наблюдениям; все восемь первичных парных интервалов после Bonferroni ниже нуля. Это не утверждение об улучшении бинарной accuracy или превосходстве над всеми стратегиями сбора данных.

## Установка

Python 3.11 или новее:

```bash

source .venv/bin/activate
python -m pip install -e .
```

В PowerShell активация: `.venv\Scripts\Activate.ps1`. Для сопоставимых CPU-измерений установите `OPENBLAS_NUM_THREADS=1` и `OMP_NUM_THREADS=1` перед запуском Python. В PowerShell: `$env:OPENBLAS_NUM_THREADS="1"; $env:OMP_NUM_THREADS="1"`.

## Протокол

Биты представлены значениями −1/+1. Признаки Arbiter PUF — суффиксные произведения challenge и константа. Веса экземпляра фиксированы. Гауссовский шум добавляется к задержке каждой цепочки перед пороговым решением; `noise` — стандартное отклонение задержки, **не вероятность ошибки бита**.

Обучающая, валидационная и тестовая выборки не пересекаются. Атаки получают только CRP; секретные веса, индивидуальные ответы XOR-цепочек и чистые ответы зашумлённого обучающего набора им не передаются. Валидационные ответы зашумлены и входят в общий бюджет; чистый тест используется только оценщиком. Архитектура и регуляризация фиксированы конфигурацией/кодом; перезапуски и эпохи нелинейных моделей выбираются по валидационной функции потерь.

При бюджете B и r повторах число обучающих challenge равно floor((B−256)/r). Неиспользованный остаток меньше r. Сравниваются один ответ на новый challenge, большинство из 3/5 ответов и доля положительных ответов из тех же 3/5 измерений. Доля используется непосредственно как мягкая метка BCE.

`accuracy` — согласие с чистой функцией PUF; `noisy_accuracy` — аналитическое ожидаемое согласие с одним новым зашумлённым ответом. Эти метрики имеют разные значения. Тестовые запросы принадлежат оценщику и не расходуют бюджет атакующего.

Интервалы 95% рассчитываются по независимым экземплярам PUF (Student t), разности стратегий — попарно по экземплярам. Интервалы исследовательские, без коррекции множественных сравнений. Несколько seed оптимизатора моделируются перезапусками внутри атаки; отдельной факторной оценки их дисперсии здесь нет. `optimizer_converged` — статус L-BFGS для линейных моделей; у Adam и константной модели оно равно `null`: критерий математической сходимости не проверяется. Трассы показывают фактически исполненные эпохи.

Дополнительно выведены зависимости среднего и ковариации условной информации Фишера от числа повторов при фиксированном бюджете. Monte Carlo-проверка на 6000 дизайнах находится в `results/fisher/`; это расчёт оценщика, не дополнительная атака. Формулы и их ограничения разобраны в приложении к отчёту.

## Границы результата

Это работа на синтетических данных: аппаратное устройство и внешняя реализация pypuf не использовались для численного подтверждения. Сравнение с литературой качественное, а не точное воспроизведение опубликованных чисел. Слабый результат конкретной модели не доказывает безопасность PUF. Повторы, reliability-based атаки и мягкие метки известны; собственный вклад — реализация, проверяемый протокол и измеренное сравнение при учёте бюджета. Приоритет новой научной идеи и право на максимальную оценку этими экспериментами не установлены.

Первичные источники и обсуждение ограничений приведены в отчёте. Использование ИИ при подготовке кода и материалов следует раскрывать в соответствии с правилами преподавателя; участники должны самостоятельно понимать и защищать результат.

## Независимая проверка на новых экземплярах

После исходного исследования выполнены ещё 300 задач на 100 новых PUF (seed 1001–1100), с фиксированными B=4096, σ=0.75 и прежними гиперпараметрами. Проверяются два заранее выбранных контраста: soft_5 против majority_5 и против single. Для парных интервалов применена поправка Bonferroni на два сравнения. Результаты и ограничения: [дополнение к отчёту](report/confirmation.pdf), [исходные данные](results/confirmation/runs.csv).

```bash
puf-attacks run --config configs/confirmation.json --output results/confirmation
puf-attacks summarize results/confirmation
python scripts/confirmation.py
```

Мягкие метки превосходят majority на 2.721 п.п. [2.554; 2.888], но уступают single на 0.193 п.п. [0.031; 0.356]. Это подтверждённое сравнение для данной постановки; оно не устанавливает научный приоритет. Основной отчёт описывает первоначальные 750 задач, дополнение — ещё 300.
